# Стандартный промпт для конспекта встречи (opencode)

Триггеры — короткая фраза в opencode:

```
Конспект: <папка>            # обработать новые записи в папке
Конспект: <путь к файлу>     # один файл (.m4a/.webm/.mp4/.mp3/.wav/.ogg/.m4b)
```

Состояние обработки ведётся в БД (`programs\zoom_state.py`, SQLite `state.db`).
Записи, идущие одна за одной (продолжение одной встречи), объединяются в **сессию** —
на сессию делается **ОДИН** конспект.

---

## Порядок работы

1. **Синхронизируй состояние** (сверяет БД с файлами, не транскрибирует):
   ```
   python programs\zoom_state.py sync
   python programs\zoom_state.py pending --json
   ```
2. **Разбери `pending`:**
   - `ready_for_konspekt` — сессии/файлы с транскриптом → делаем конспект (**по сессии — один**);
   - `no_transcript` — транскрипта нет → **пропускаем** (транскрибацию не запускать без согласия пользователя).
3. **Для каждой готовой сессии** составь **один компактный конспект** (шаблон ниже).
4. **Сохрани** (рядом с аудио — по первому файлу сессии — и в Obsidian) и **отметь:**
   - сессия:
     ```
     python programs\zoom_state.py session done <id> --konspekt "<abs>\<первый>_конспект.md" --obsidian "<rel>"
     ```
   - одиночный файл (нет сессии):
     ```
     python programs\zoom_state.py mark "<аудио>" done --konspekt "<папка>\<имя>_конспект.md" --obsidian "<rel>"
     ```

## Структура конспекта (компактная)

```markdown
---
дата: ГГГГ-ММ-ДД
начало: "ЧЧ:ММ"
длительность: "ММ:СС"
файлы: [файл1.m4a, файл2.m4a]      # для сессии — все файлы
участники: [Имя1, Имя2(?)]
теги: [тема1, тема2]
---
# Тема

**Суть:** главный вывод одной строкой.

Обзор: 2–4 предложения — что обсудили, что рассмотрели, к чему пришли (только суть и итог, без деталей).

## Ключевые решения
- Решение законченной фразой — Кто, срок (если известно)
- …

## Важные обновления статуса
- Что изменилось / факт состояния — ==цифры и риски выделять==

## Следующие шаги
- [ ] шаг с глагола — исполнитель, срок

## Открытые вопросы
- Как … ? / Кто … ? / Где … ?

## Хронология (опционально)
- `[мм:сс]` якорь — одна фраза      # по умолчанию 3–7 пунктов; полный таймлайн — по запросу
```

## Правила

- **Обзорный абзац обязателен** — синтез встречи (как executive summary), без пересказа по минутам.
- **Ключевые решения** — буллеты **законченными фразами** (не телеграф): каждое решение понятно без контекста;
  в конце — `— Кто, срок`, если известно. Таблицу не использовать.
- **Важные обновления статуса** — факты и изменения состояния (цифры, ресурсы, ограничения); цифры/риски — `==…==`.
  Пустую секцию опускать.
- **Следующие шаги** — чек-лист `- [ ] <шаг> — исполнитель, срок`.
- **Открытые вопросы** — формулировать **как вопросы** (`Как … ?`, `Кто … ?`), а не как задачи.
- **Хронология** — опциональна: по умолчанию **3–7 якорных пунктов** `[мм:сс]`; полный таймлайн — только по запросу
  или для сложной встречи.
- **Frontmatter обязателен** (даёт Dataview-сводки): `дата/начало/длительность/файлы/участники/теги`.
- Для сессии: `начало` — по первому файлу, `длительность` — суммарная, `файлы` — все файлы сессии.
- Ничего не выдумывай; неразборчивые места — `[неразборчиво]`; имена — с заглавной буквы, при сомнении `Имя(?)`
  (в отличие от авто-саммари, имена не пишем со строчной); термины (1С, ИТ) корректно; тон деловой, без воды.

### Технические правила (обязательные)

- **Длинный транскрипт (> ~1500 строк .srt) читай по частям** — диапазонами по 400–800 строк
  (инструмент чтения с `line_start/line_end`), а не целиком: иначе контекст переполняется, и конспект
  молча не пишется. Сначала просмотри начало/конец каждой части, затем углубляйся.
- **Всегда проверь результат записи**: после сохранения прочитай файл и убедись, что в нём есть
  `## Ключевые решения` и абзац `Обзор:`. Если нет — допиши, а не отчитайся «готово».
- **Не перезаписывай файл «на месте» вслепую**: сначала прочитай существующий конспект, сохрани из его
  frontmatter `дата/начало/длительность/файлы/участники`, тему (H1) и теги.
- **Срок у поручения/решения** — конкретный (`сегодня`, `до пятницы`, `следующая неделя`, `—`);
  избегай бессодержательного «сейчас» у каждого пункта.
- Не дублируй один и тот же факт в «Ключевых решениях» и «Следующих шагах»: решения = что решили,
  шаги = что конкретно сделать (с действием).

## Самопроверка (перед отчётом)

1. Файл конспекта существует, не пустой, начинается с `---` (frontmatter).
2. В нём есть: обзорный абзац (`Обзор:`) и секции `Ключевые решения` / `Следующие шаги` /
   `Открытые вопросы` (пустые секции удалены).
3. Объём конспекта — **не более ~60 строк**, хронология — не длиннее 7 пунктов.
4. Нет дословного дублирования между «Ключевыми решениями» и «Следующими шагами».
5. Нет `Таблица Кто|Что|Срок`, нет секций старого стиля («Решения», «Поручения», «❗Риски / цифры», «Открыто»).
6. Если что-то не удалось — скажи прямо, какие пункты не удалось, а не сообщай «готово».

## Сохранение и публикация

1. **Локально** (единственный файл, который ты пишешь): рядом с аудио —
   `<папка встречи>\<первый файл сессии>_конспект.md`.
2. **В Obsidian не пиши вручную.** Заметку создаёт команда (она делает копию твоего файла,
   поэтому расхождений и дублей не будет):
   ```
   python programs\zoom_state.py publish "<локальный конспект>" --obsidian "Обсидиан/Встречи Zoom/ГГГГ/ММ/ГГГГ-ММ-ДД/ЧЧ-ММ — <тема>.md"
   ```
   Имя заметки — время по **первому файлу** сессии + тема; путь **от корня vault** `E:\Обсидиан\Обсидиан`,
   поэтому первый компонент — `Обсидиан` (заметки физически лежат в
   `E:\Обсидиан\Обсидиан\Обсидиан\Встречи Zoom\...`). Команда сама проставит в БД `obsidian_path`
   и статус `done` (всем файлам сессии).

## Примечания

- **Сессии** (объединение встреч-продолжений): `session auto --gap 30` предлагает группы по зазору между
  записями (по умолч. 30 с); `session merge` / `session split` — ручной контроль. При расхождении тем
  сомнительное объединение разъединяем вручную (`session split`).
- Транскрипция полностью локальная (токены LLM только на чтение транскрипта + генерацию конспекта).
- Движок транскрибации: `-Engine gigaam` (по умолч.) | `nemotron` | `whisper` в `transcribe.ps1` / `transcribe-all.ps1`.
- **Поддерживаемые форматы записи** (транскрибируются любые, не только `.m4a`): `.m4a`, `.webm`, `.mp4`, `.mp3`,
  `.wav`, `.ogg`, `.m4b` — `transcribe-all.ps1`/`transcribe.ps1` конвертируют через ffmpeg в WAV 16 кГц моно.
  Пример: телемост-запись `(Встреча в Телемосте 24.09.26 09-23-24 - запись).webm` — транскрибирована успешно (24.09).
- Таймкоды — из `.srt`, текст — из `.srt`/`.txt`.
- Быстрый/черновой вариант whisper-транскрибации: `-Engine whisper -Model ggml-small.bin`.
- Экономия места: `transcribe.ps1 -DeleteTxt` удалит `.txt`, оставив `.srt`.

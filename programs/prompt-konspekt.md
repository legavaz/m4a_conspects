# Стандартный промпт для конспекта встречи (opencode)

Триггеры — короткая фраза в opencode:

```
Конспект: <папка>            # обработать новые записи в папке
Конспект: <путь к .m4a>      # один файл
```

Состояние обработки ведётся в БД (`programs\zoom_state.py`, SQLite `state.db`).
Записи, идущие одна за одной (продолжение одной встречи), объединяются в **сессию** —
на сессию делается **ОДИН** конспект.

---

## Порядок работы

1. **Синхронизируй состояние** (сверяет БД с файлами, не транскрибирует):
   ```
   python programs\zoom_state.py sync
   python programs\zoom_state.py pending --json
   ```
2. **Разбери `pending`:**
   - `ready_for_konspekt` — сессии/файлы с транскриптом → делаем конспект (**по сессии — один**);
   - `no_transcript` — транскрипта нет → **пропускаем** (транскрибацию не запускать без согласия пользователя).
3. **Для каждой готовой сессии** составь **один компактный конспект** (шаблон ниже).
4. **Сохрани** (рядом с аудио — по первому файлу сессии — и в Obsidian) и **отметь:**
   - сессия:
     ```
     python programs\zoom_state.py session done <id> --konspekt "<abs>\<первый>_конспект.md" --obsidian "<rel>"
     ```
   - одиночный файл (нет сессии):
     ```
     python programs\zoom_state.py mark "<аудио>" done --konspekt "<папка>\<имя>_конспект.md" --obsidian "<rel>"
     ```

## Структура конспекта (компактная)

```markdown
---
дата: ГГГГ-ММ-ДД
начало: "ЧЧ:ММ"
длительность: "ММ:СС"
файлы: [файл1.m4a, файл2.m4a]      # для сессии — все файлы
участники: [Имя1, Имя2(?)]
теги: [тема1, тема2]
---
# Тема

**Суть:** одна строка — что произошло и к чему пришли.

## Решения
| Кто | Что | Срок |
|---|---|---|
| … | … | … |

## Поручения
- [ ] исполнитель — что — срок

## Хронология
- `[мм:сс]` тема — одна фраза
- `[мм:сс]` …

## ❗Риски / цифры
- ==риск или цифра==

## Открыто
- [ ] вопрос
```

## Правила

- **Решения** — таблицей `кто | что | срок`; **Поручения** — чек-лист `- [ ]`; пустую секцию опускать.
- **«Хронология»** — таймлайн `[мм:сс] тема — одна фраза`; подробный блок — только для сложной встречи (по запросу).
- **Frontmatter обязателен** (даёт Dataview-сводки): `дата/начало/длительность/файлы/участники/теги`.
- Для сессии: `начало` — по первому файлу, `длительность` — суммарная, `файлы` — все файлы сессии.
- Ничего не выдумывай; неразборчивые места — `[неразборчиво]`; имена и термины (1С, ИТ) корректно;
  ❗ — только цифры/риски/дедлайны; тон деловой, без воды.

## Сохранение (два места)

- рядом с аудио: `<папка>\<первый файл сессии>_конспект.md`;
- в Obsidian: `Обсидиан/Встречи Zoom/ГГГГ/ММ/ГГГГ-ММ-ДД/ЧЧ-ММ — <тема>.md`
  (время — по **первому файлу** сессии; записи дня идут по порядку).

---

## Примечания

- **Сессии** (объединение встреч-продолжений): `session auto --gap 30` предлагает группы по зазору между
  записями (по умолч. 30 с); `session merge` / `session split` — ручной контроль. При расхождении тем
  сомнительное объединение разъединяем вручную (`session split`).
- Транскрипция полностью локальная (токены LLM только на чтение транскрипта + генерацию конспекта).
- Таймкоды — из `.srt`, текст — из `.srt`/`.txt`.
- Быстрый/черновой вариант транскрибации: `-Model ggml-small.bin`.
- Экономия места: `transcribe.ps1 -DeleteTxt` удалит `.txt`, оставив `.srt`.
